P7 — Agente com Google ADK

Semanas: 13–15 | Degrau: 3
Tópicos: Google ADK — Agent Development Kit · Agent Orchestration
Cobre do perfil da função: Google ADK, agentic orchestration, "automated support agents"

Pré-condição — justifique o agente

Responda por escrito antes de começar:

"Esta tarefa exige decisão dinâmica multi-passo onde a sequência não pode
ser predeterminada?"

Se a resposta for não, o certo é um prompt chain. Documente a justificativa.
O PDF é claro que pular essa pergunta é o erro mais comum de engenharia de IA aplicada.

Estrutura em duas etapas (importante)

Etapa 1 (semana 13): ReAct na mão

Construa o loop reason → act → observe sem framework nenhum.
Só Vertex AI + function calling + um while loop.

Motivo: o PDF adverte que frameworks escondem o que acontece. Você precisa saber
o que o ADK está fazendo por baixo antes de confiar nele.

Etapa 2 (semanas 14–15): reconstruir com ADK

Mesma funcionalidade, agora com o ADK. Compare:
- Quanto código você economizou?
- O que ficou mais difícil de debugar?
- O que o ADK dá de graça (sessions, eval, deploy)?

⚠️ Escreva o código lendo a doc oficial atual (https://google.github.io/adk-docs/).
Não confie em exemplos de blog — a API mudou desde meu conhecimento (maio/2026).

O que o agente faz

Assistente de triagem para o time de Support.

Tools disponíveis:

Tool Origem Função
search_docs P5 RAG na documentação
search_jira P6 Buscar tickets similares (JQL)
create_ticket P6 Criar issue
notify_slack P6 Postar no canal

Note que todas as tools vêm dos projetos anteriores. Por isso P6 veio antes de P7.

Failure modes — cada um vira um teste

Failure Teste
Tool misuse Tool retorna erro → agente lida ou trava?
Reasoning drift Task longa → agente ainda persegue o objetivo?
Infinite loop Hard cap de iterations existe e funciona?
Context overflow Run longa → sumarização acontece?
Cost explosion Budget por run existe e corta?
Prompt injection via tool Ticket com "ignore instruções" → agente resiste?

Human-in-the-loop

O PDF avisa: "High-stakes irreversible actions without human-in-the-loop"
é caso de não usar agente.

Criar ticket é reversível. Fechar ticket de cliente, não.
Defina quais ações exigem confirmação humana e implemente isso.

Entregável

p7_adk_agent/
├── manual/
│   └── react_loop.py       # etapa 1 — sem framework
├── adk/
│   ├── agent.py            # etapa 2 — com ADK
│   └── tools/
├── tests/test_failure_modes.py
├── deploy/                 # Agent Engine
└── docs/
    ├── decision_log.md     # por que agente
    └── manual_vs_adk.md    # comparação honesta

Definition of Done

  • ReAct loop na mão funcionando (etapa 1)
  • Mesma funcionalidade com ADK (etapa 2)
  • Comparação escrita: o que o ADK abstrai
  • 6 failure modes testados
  • Hard cap de iterations
  • Human-in-the-loop nas ações irreversíveis
  • Deployado no Agent Engine
  • Custo por run monitorado
