P5 — RAG sobre Documentação (caso Legal)

Semanas: 9–10 | Degrau: 2
Tópico: RAG — Architecture, Patterns & Failure Modes
Cobre do perfil da função: "intelligent documentation retrieval", "contract review automations"

Pré-condição — aplique o decision framework

Antes de escrever código, responda por escrito:

  1. Precisa de conhecimento fora do modelo? → sim (docs internos)
  2. Cabe tudo no context window? → provavelmente não
  3. Acurácia + citação obrigatórias? → sim, é Legal

E antes de construir do zero:
- Avaliei grounding nativo do Vertex AI
- Avaliei Vertex AI Search
- Documentei por que precisei de pipeline próprio (se precisei)

Cenário

Base de políticas e contratos-modelo. Perguntas típicas:
"Qual é o prazo de rescisão no contrato padrão de merchant?"

⚠️ Use documentos públicos ou sintéticos. Não coloque documento interno real
da sua empresa num projeto de estudo sem aprovação. Se quiser usar dados reais,
alinhe com segurança/compliance primeiro.

Pipeline

Docs (PDF/Confluence export)
  → decisão: chunkar ou não?
  → parent-child chunking (cláusula → contrato)
  → embeddings
  → pgvector (Postgres — está no perfil da função)

Query
  → BM25 + vector search
  → RRF merge
  → reranking
  → prompt com grounding
  → resposta com citação obrigatória

Grounding instruction (não negocie isso)

Responda APENAS com base no contexto fornecido.
Se a resposta não estiver no contexto, diga:
"Não encontrei essa informação na base de documentos."
Cite o documento e a seção para cada afirmação.
Nunca infira ou complete informação ausente.

Para Legal, uma resposta inventada é pior que nenhuma resposta.

Failure modes a testar (todos do PDF)

  • Semantic mismatch: "rescisão" encontra doc que diz "término antecipado"?
  • Chunk fragmentation: resposta que atravessa duas cláusulas
  • Top-k pequeno: aumentei K e melhorou?
  • Stale index: atualizei doc, retrieval reflete?
  • Context poisoning: chunk irrelevante estragou a resposta?
  • Hallucination apesar do contexto: modelo inventou cláusula?

Eval com Ragas

Metas mínimas: faithfulness > 0.85 · answer relevancy > 0.80

Use TestsetGenerator para gerar QA pairs do próprio corpus —
resolve a falta de dataset anotado.

Entregável

p5_rag_legal/
├── ingest.py
├── retriever.py            # hybrid + RRF
├── rag.py
├── eval/
│   ├── testset.json
│   └── ragas_results.md
├── tests/test_failure_modes.py
└── docs/decision_log.md    # por que RAG, por que esse chunking

Definition of Done

  • Decision log escrito (incl. por que não usei só grounding nativo)
  • Hybrid search com RRF
  • Todos os 6 failure modes testados
  • Ragas dentro das metas
  • Sistema responde "não encontrei" quando não sabe (testado)
  • Toda resposta tem citação
