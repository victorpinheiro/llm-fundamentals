P3 — Evaluation Pipeline (CI-ready)

Semanas: 5–6 | Degrau: 1
Tópico: Evaluation & Testing
Cobre do perfil da função: applied ML workflows, engenharia de qualidade

Objetivo

Pipeline de avaliação que roda no pytest e no CI. Este é o entregável que
transforma "eu acho que funciona" em "aqui estão os números".

Numa conversa com Legal ou Compliance, isso é o que dá confiança pra aprovar.

O que construir

Sobre o classificador do P2:

  1. Golden set de 40 casos com labels acordadas
  2. Unit tests com DeepEval rodando via pytest
  3. LLM-as-judge com critérios categóricos (PASS/FAIL)
  4. Regression gate no CI — falha se qualidade cair

Golden set — estrutura

{
  "id": "test_001",
  "input": "pagamento falhou 3x, cliente irritado",
  "expected_category": "billing",
  "expected_urgency_range": [4, 5],
  "difficulty": "easy",
  "tags": ["billing", "urgent"]
}

Distribuição (PDF): 15 easy · 15 medium · 7 edge · 3 adversarial

LLM-as-judge — categórico, nunca numérico

Regra do PDF:

✅  "JSON_VALID: PASS/FAIL, CATEGORY_CORRECT: PASS/FAIL"
❌  "Nota de 1 a 10"

Regression gate no CI

O CI deve falhar se:
- Taxa de acerto de categoria < 85%
- JSON válido < 100%
- Qualquer caso adversarial passar pelo guardrail

Entregável

p3_evaluation/
├── golden_set/
│   ├── cases.json          # 40 casos
│   └── CHANGELOG.md        # versionamento do golden set
├── tests/
│   ├── test_unit.py
│   ├── test_regression.py
│   └── judge.py
├── .github/workflows/eval.yml
└── report/baseline.md

Definition of Done

  • Golden set de 40 casos versionado no git
  • deepeval test run passando localmente
  • CI rodando eval em todo PR
  • CI falhando de propósito (testei o gate)
  • Judge usando PASS/FAIL, não escala numérica
  • Baseline documentado (números de partida)
