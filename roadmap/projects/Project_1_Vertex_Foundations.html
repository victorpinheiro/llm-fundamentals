P1 — Vertex AI Foundations

Semanas: 1–2 | Degrau: 1
Tópicos: Google Vertex AI — Plataforma de Referência · LLM Fundamentals
Cobre do perfil da função: Vertex AI, Gemini, integração de modelos de terceiros

Objetivo

Rodar seu primeiro sistema no stack real da função: Vertex AI com autenticação
de service account, structured output, e medição de custo/latência.

Você também vai chamar Anthropic e OpenAI para comparação — o perfil da função pede
capacidade de escolher entre modelos, não devoção a um.

O que construir

Classificador de tickets de suporte interno (contexto: time de Support da sua empresa)

  • Input: texto livre de um pedido interno
  • Output: JSON estruturado (categoria, urgência, time responsável, resumo)
  • Rodando em Vertex AI/Gemini como default
  • Com comparação contra Claude e GPT nos mesmos inputs

Especificação

Input:  "o merchant X não está recebendo webhooks desde ontem, urgente"

Output: {
  "category": "technical_integration",
  "urgency": 4,
  "team": "merchant_support",
  "summary": "Webhook delivery failure for merchant since yesterday",
  "requires_escalation": true,
  "_meta": {
    "model": "gemini-flash",
    "latency_ms": 380,
    "tokens_in": 94,
    "tokens_out": 51,
    "cost_usd": 0.000018
  }
}

Requisitos técnicos

  • Autenticação via ADC/service account (não use API key)
  • Vertex AI SDK para Python
  • Structured output via response schema (confirmar sintaxe na doc)
  • Temperature = 0 (tarefa de extração)
  • Instrumentação: latência, tokens, custo em cada call
  • Comparação Gemini vs Claude vs GPT nos mesmos 20 inputs

⚠️ Confirme a sintaxe atual do SDK na doc. Não copie código de blog post antigo —
a API do Vertex mudou várias vezes.

Entregável

p1_vertex_foundations/
├── classifier.py
├── schemas.py              # Pydantic
├── providers/
│   ├── vertex.py           # default
│   ├── anthropic.py        # comparação
│   └── openai.py           # comparação
├── benchmark.py
├── results/
│   └── comparison.md       # latência, custo, qualidade
└── tests/

Definition of Done

  • 20 inputs classificados com sucesso
  • JSON válido em 100% das calls, zero regex
  • Auth por service account funcionando
  • Tabela comparativa dos 3 provedores preenchida
  • Conclusão escrita: qual modelo você usaria em produção e por quê
  • Custo projetado para 1.000 calls/dia calculado
