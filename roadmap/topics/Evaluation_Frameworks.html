Evaluation & Testing

Fase: 1 | Semanas: 5–6 | Projeto: P3 — Evaluation Pipeline (CI-ready)

PDF: "AI testing is an extension of software testing, not a separate research
discipline." DeepEval integra nativamente com pytest — você já sabe fazer isso.

O perfil da função pede "applied ML workflows". Evaluation é a parte disso que mais importa
para quem entrega IA — é o que prova que a solução funciona.

Por que é diferente de software tradicional

  • Outputs não-determinísticos: mesmo prompt → outputs diferentes
  • "Correto" é frequentemente subjetivo
  • assert output == expected é inválido
  • Mesmo com temperature=0, updates do modelo mudam outputs

A Hierarquia (PDF)

Nível O que testa Ferramenta Quando
Unit Formato, toxicidade, constraints DeepEval Toda mudança de prompt
Integration Pipeline: RAG recupera certo? Ragas, DeepEval Mudanças de arquitetura
Regression Update quebrou casos que passavam? Golden set + CI Todo release
Red team Prompt injection, jailbreak, edge Manual + adversarial Antes de produção

LLM-as-a-Judge

Regra crítica do PDF:

"Use categorical evaluations (Pass/Fail, Good/Neutral/Bad) rather than
numeric scores (1–10). LLMs produce inconsistent results on continuous scales —
even slight prompt wording changes shift scores."

✅ "Rate this response: PASS or FAIL"
❌ "Rate this response from 1 to 10"

Ragas para RAG

Métricas: retrieval precision, retrieval recall, faithfulness, answer relevancy.

Killer feature (PDF): TestsetGenerator gera QA pairs sintéticos a partir
do seu próprio corpus. Resolve o problema real de não ter dataset anotado —
que é exatamente a situação de qualquer time interno da sua empresa.

Golden Set — best practices (PDF)

  • Comece com 25–50 casos curados
  • Inclua: happy path, edge cases, adversarial, out-of-scope
  • Expanda quando encontrar novo failure pattern
  • Versione junto com prompts e código
