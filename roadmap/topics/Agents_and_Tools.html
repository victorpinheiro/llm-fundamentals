Agent Orchestration

Fase: 2 | Semanas: 13–17 | Projetos: P7 — Agente com Google ADK | P8 — Multi-Agent (só com evidência)

A pergunta antes de tudo (PDF)

"Does this task require dynamic, multi-step decision-making where the sequence
of steps cannot be predetermined? If no — a prompt chain or a single LLM call
is simpler, faster, cheaper, and easier to debug."

O perfil da função pede "automated support agents", mas isso não significa que todo caso
precisa de agente. Saber dizer "isso aqui não precisa de agente" é sinal de
senioridade — e é exatamente o que o PDF chama de erro mais comum de engenharia de IA aplicada.

Quando NÃO usar agente (PDF)

  • Tarefa single-step → direct LLM call
  • Latência estrita (<1s) → agentes são lentos
  • Ação irreversível sem human-in-the-loop → perigoso
  • Cabe em um context window → single model + toolbox
  • Custo restrito → agentes consomem muito mais tokens

"With 1M+ token context windows, many use cases that used to require agents
can now be handled by a single model with a full toolbox."

Padrões (PDF)

1. Single Agent + Toolbox — DEFAULT. Um LLM, todas as tools, ReAct loop.
Comece aqui sempre.

2. Orchestrator + Subagents. Router delega a especialistas.
Cada subagente adiciona latência, custo e nova superfície de falha.

3. Pipeline (Sequential Chain). Output de N alimenta N+1. Determinístico.
Não é "agentic", mas frequentemente suficiente e muito mais fácil de debugar.

4. Parallel Agents. Subtarefas independentes em paralelo.
Requer lógica de merge e resolução de conflito.

Failure Modes (PDF) — cada um com mitigação

Failure Descrição Mitigação
Tool misuse Args errados, tool errada, ignora erro da tool Validar outputs; error handling no wrapper; schemas estritos
Reasoning drift Erros pequenos se acumulam, desvia do objetivo Validação por step; max iterations; goal-checking
Infinite loops Repete a mesma ação sem progresso Hard cap; detectar tool calls repetidos
Context overflow Run longa enche o context window Sumarizar e comprimir histórico
Cost explosion Consome muito mais token que o previsto Token budget; log e alerta por run
Prompt injection via tools Tool retorna instrução maliciosa Sanitizar; tratar output de tool como untrusted

⚠️ O último é crítico no contexto do perfil da função: seu agente vai ler mensagens do Slack e
tickets do Jira. Isso é conteúdo escrito por humanos, não confiável por definição.

Checklist

  • Documentei por que agente era necessário (não foi default)
  • Construí ReAct loop na mão antes de usar framework
  • Single agent + toolbox funcionando
  • Os 6 failure modes testados e mitigados
  • Hard cap de iterations
  • Sanitização de tool outputs (prompt injection)
  • Multi-agent só após medir insuficiência do single agent
