LLM Fundamentals

Fase: 1 | Semanas: 1–2 | Projeto: P1 — Vertex AI Foundations

PDF: "Think of it as a stateless HTTP endpoint. Every call is independent.
'Intelligence' is pattern matching at massive scale, not a reasoning process."

Conceitos que um engenheiro de IA sabe de cor

Context Window

  • É RAM, não disco. Tudo relevante precisa caber.
  • Lost-in-the-middle: modelos recuperam bem o começo e o fim, degradam no meio.
  • Regra: informação crítica no começo ou no fim do prompt. Nunca no meio.

Tokens

  • ~0,75 palavras por token em inglês. Código tokeniza diferente de prosa.
  • Token = unidade de billing + consumo de contexto.
  • PDF de 10 páginas ≈ 4.000 tokens.
  • Sempre estime tokens antes de construir um pipeline.

Temperature

  • 0 → determinístico. Extração, classificação, structured output.
  • 0.7–1.0 → criativo. Geração, brainstorm.
  • Regra: se corretude importa, temperature = 0.

Embeddings

  • Modelo separado, menor e mais barato que o LLM de geração.
  • Não misture provedores de embedding — degrada qualidade.
  • Backbone do RAG.

Fine-tuning vs Prompting

Prompting Fine-tuning
Quando Sempre primeiro Só após esgotar prompting
Custo Só inferência Treino + inferência
Ensina bem Comportamento, formato Estilo, formato consistente
Não ensina — Conhecimento factual novo

Esse último ponto derruba muita proposta ruim: fine-tuning não injeta fatos.
Se o problema é conhecimento, a resposta é RAG.

Checklist

  • Primeira call ao Gemini via Vertex AI
  • Calculei custo de 1.000 calls no modelo escolhido
  • Testei context window com prompt grande (vi o lost-in-the-middle na prática)
  • Testei temperature 0 vs 0.7 na mesma tarefa
  • Entendo por que fine-tuning não resolve knowledge gap
