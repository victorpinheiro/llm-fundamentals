Módulo 1 — Fundamentos de Modelos de Linguagem

Projeto: P1 — Primeira Integração com Saída Estruturada · Conceito: Referência — Fundamentos de Modelos

Objetivo

Ao final você conseguirá integrar um modelo de linguagem via API,
prever o custo de uma chamada antes de fazê-la, e explicar por que
esses sistemas se comportam como se comportam.

Por que importa

Quase todo erro de arquitetura em sistemas de IA vem de um mal-entendido
sobre o que o modelo é. Quem trata o modelo como um banco de dados que
"sabe coisas" constrói sistemas que alucinam. Quem trata como um serviço
com memória constrói sistemas que perdem contexto silenciosamente.

Conceitos

O modelo é sem estado

Um modelo de linguagem é uma função: texto entra, texto sai. Ele não
lembra da chamada anterior. Toda "memória" de uma conversa é você
reenviando o histórico a cada chamada.

Consequência prática: conversas longas ficam progressivamente mais caras,
porque você reenvia tudo toda vez.

Janela de contexto

O limite de texto (entrada + saída) que cabe em uma chamada.
Pense em memória RAM, não em disco: o que não está na janela, o modelo
não tem acesso naquela chamada.

Efeito do meio perdido: modelos recuperam bem informação no começo e
no fim do contexto, e degradam no meio. Isso está bem documentado e tem
uma consequência direta de engenharia: coloque instruções críticas no
início ou no fim do prompt, nunca no meio de um bloco longo.

Tokens

Texto é fragmentado em tokens antes do processamento. Aproximadamente
0,75 palavra por token em inglês; outras línguas e código variam bastante.

Tokens são simultaneamente:
- a unidade de cobrança
- a unidade de consumo da janela de contexto

Estime tokens antes de projetar qualquer pipeline. Um documento de dez
páginas gira em torno de 4.000 tokens — multiplicado por mil documentos,
isso deixa de ser detalhe.

Temperatura

Controla a aleatoriedade da amostragem.

Valor Uso
0 Extração, classificação, saída estruturada
0.7–1.0 Geração criativa, brainstorming

Regra simples: se corretude importa mais que variedade, use 0.

Embeddings

Representações vetoriais de texto que capturam significado. Textos
semanticamente próximos ficam próximos no espaço vetorial.

São gerados por um modelo separado — menor, mais rápido e mais barato
que o modelo de geração. Não misture provedores de embedding dentro do
mesmo índice: os espaços vetoriais são incompatíveis.

Prompt versus fine-tuning

Prompt Fine-tuning
Quando usar Sempre primeiro Só depois de esgotar prompt
Custo Apenas inferência Treino + inferência
Reversível Sim, imediato Não
Ensina bem Comportamento, formato Estilo e formato consistentes
Não ensina — Conhecimento factual novo

A última linha derruba muita proposta ruim. Se o problema é o modelo não
conhecer seus dados, fine-tuning não resolve — RAG resolve.

SDKs diretos dos provedores, autenticação por chave de API.
Compare pelo menos dois provedores na mesma tarefa.

Trilha B

P1 — Primeira Integração com Saída Estruturada — classificador com saída estruturada e

Autoavaliação

Responda por escrito, sem consultar:

  1. Por que uma conversa de 20 turnos custa mais que uma de 2 turnos,
    mesmo que as mensagens tenham o mesmo tamanho?
  2. Onde você coloca uma instrução crítica num prompt de 50 mil tokens?
    Por quê?
  3. Um cliente quer que o modelo conheça o catálogo de produtos da empresa.
    Fine-tuning ou RAG? Justifique.
  4. Você precisa extrair CNPJs de documentos. Que temperatura usa?
  5. Estime o custo de processar 5.000 documentos de 8 páginas.

Erros comuns

Erro Por que acontece Correção
Assumir que o modelo lembra Interface de chat sugere memória Reenviar histórico explicitamente
Temperatura alta em extração Padrão do SDK não é 0 Definir explicitamente
Misturar provedores de embedding Parecem intercambiáveis Um provedor por índice
Propor fine-tuning para conhecimento Confusão comum RAG
Não estimar custo antes Testes iniciais são baratos Calcular para escala real
