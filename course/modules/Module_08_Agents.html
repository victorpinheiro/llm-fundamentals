Módulo 8 — Agentes e Uso de Ferramentas

Projeto: P7 — Agente com Ferramentas · Conceito: Referência — Agentes

Objetivo

Saber quando um agente é a resposta certa — e quando não é — construir
um com uso de ferramentas, e mitigar cada modo de falha conhecido.

A pergunta que vem antes

Esta tarefa exige decisão dinâmica de múltiplas etapas, em que a
sequência de passos não pode ser determinada de antemão?

Se a resposta for não, uma cadeia de prompts ou uma única chamada é mais
simples, mais rápida, mais barata e muito mais fácil de depurar.

Saber recusar um agente é sinal de senioridade. O erro mais comum
entre quem está aprendendo é usar agente por ser a solução mais
interessante, não a mais adequada.

O que é um agente

Um modelo com ferramentas e autonomia para decidir quais usar e quando.
Opera em laço:

raciocinar → agir (chamar ferramenta) → observar resultado → raciocinar

O laço termina quando o objetivo é atingido ou quando um limite é atingido.

Quando não usar

  • Tarefa de passo único — chamada direta resolve
  • Latência crítica — agentes são inerentemente mais lentos
  • Ação irreversível sem confirmação humana — risco desproporcional
  • Tudo cabe em uma janela de contexto — modelo único com ferramentas
  • Orçamento apertado — agentes consomem muito mais tokens

Com janelas de contexto cada vez maiores, muitos casos que antes exigiam
agentes hoje são resolvidos por um único modelo bem instrumentado.

Padrões de arquitetura

Agente único com caixa de ferramentas

Este é o padrão inicial. Um modelo, todas as ferramentas, um laço.
Comece sempre aqui. Só adicione complexidade com motivo concreto.

Orquestrador com subagentes

Um roteador delega a especialistas. Cada subagente acrescenta latência,
custo e uma nova superfície de falha. Justifique antes de adotar.

Cadeia sequencial

Saída de uma etapa alimenta a próxima, sem ramificação. Não é
propriamente um agente, mas frequentemente é suficiente — e muito mais
fácil de depurar.

Agentes em paralelo

Subtarefas independentes simultâneas. Reduz tempo total, exige lógica
de mesclagem e resolução de conflito.

Projeto de ferramentas

A qualidade das ferramentas determina a qualidade do agente.

Princípio Motivo
Descrição clara e específica O modelo escolhe pela descrição
Esquema estrito de parâmetros Reduz chamadas malformadas
Erro informativo O agente precisa poder se recuperar
Idempotência quando possível Repetição não deve causar dano
Cálculo delegado a ferramenta Modelos erram aritmética

Uma ferramenta com descrição vaga é escolhida na hora errada. Se o agente
usa a ferramenta errada com frequência, o problema costuma ser a descrição,
não o modelo.

Modos de falha

Falha O que acontece Mitigação
Uso incorreto de ferramenta Argumentos errados, ferramenta errada, erro ignorado Validar saída; tratamento de erro; esquema estrito
Deriva de raciocínio Erros pequenos se acumulam e o objetivo se perde Validação por etapa; limite de iterações; verificação de objetivo
Laço infinito Repete a mesma ação sem progresso Limite rígido; detectar repetição
Estouro de contexto Execução longa enche a janela Resumir e comprimir histórico
Explosão de custo Consumo muito acima do previsto Orçamento por execução com corte
Injeção via ferramenta Resultado de ferramenta contém instrução Sanitizar; tratar como dado

Implemente cada mitigação como um teste. Um agente sem esses testes
não está pronto para produção.

Humano no laço

Ações irreversíveis exigem confirmação. Defina explicitamente a fronteira:

Reversível Irreversível
Criar rascunho Enviar mensagem externa
Ler dados Apagar registro
Abrir tarefa Fechar caso de cliente
Sugerir Executar transação

Na dúvida, exija confirmação. O custo de uma confirmação a mais é baixo;
o de uma ação irreversível errada, não.

Trilha A

Construa o laço manualmente primeiro, depois compare com um framework
de orquestração. Ver Trilha A — OpenAI e Anthropic.

Trilha B

O kit de desenvolvimento da plataforma passou por reescrita significativa.
Ver Trilha B — Plataforma Corporativa do Google Cloud e confirme a versão antes de estudar.

Projeto

P7 — Agente com Ferramentas — em duas etapas: laço manual, depois com framework.

Autoavaliação

  1. Qual a pergunta que precede qualquer decisão sobre usar agente?
  2. Dê um exemplo que parece exigir agente mas não exige.
  3. Cite os seis modos de falha e uma mitigação para cada.
  4. Como decidir se uma ação precisa de confirmação humana?
  5. Seu agente escolhe a ferramenta errada com frequência. Onde investigar?

Erros comuns

  • Usar agente por padrão
  • Descrições de ferramenta vagas
  • Sem limite de iterações
  • Deixar o agente fazer contas
  • Tratar resultado de ferramenta como confiável
  • Ação irreversível sem confirmação
