Trilha A — OpenAI e Anthropic

Leia Aviso de Volatilidade antes. Nomes de modelo mudam com frequência;
confirme na documentação oficial.

Filosofia desta trilha

Construir com SDKs diretos, sem camada de abstração. Você vê cada peça:
como a autenticação funciona, como o contexto é montado, como o laço do
agente executa.

É o caminho mais lento em linhas de código e o mais rápido em compreensão.

Setup

pip install openai anthropic pydantic python-dotenv

Autenticação por chave de API em variável de ambiente.
Configure limite de gasto no painel de cada provedor antes de começar.

Camadas de modelo

Os dois provedores organizam a oferta em camadas equivalentes:

Camada Característica Uso
Maior Melhor qualidade, mais caro e lento Análise complexa, alto risco
Intermediária Equilíbrio Maioria dos casos
Menor Rápido e barato Classificação, roteamento
Raciocínio Otimizado para lógica Código, matemática, planejamento

Não decore nomes de modelo. Consulte a documentação de modelos do
provedor no momento em que for implementar e escolha pela camada.

Saída estruturada

Ambos suportam nativamente, com mecanismos diferentes:

  • Um usa um modo dedicado de saída em esquema
  • Outro usa o mecanismo de ferramentas para forçar formato

Aprenda os dois. A diferença de abordagem ensina algo sobre como cada
provedor pensa o problema.

Combine sempre com validação por modelo de dados no seu código.
O provedor garante formato; você garante semântica.

Uso de ferramentas

Os dois suportam chamada de função com esquema declarado. O fluxo é o
mesmo em ambos:

  1. Você declara as ferramentas disponíveis
  2. O modelo indica qual quer chamar e com quais argumentos
  3. Você executa e devolve o resultado
  4. O modelo continua a partir dali

Você controla o laço. Isso é a essência de um agente construído à
mão, e é o que o Módulo 8 pede que você faça antes de usar framework.

Cache de contexto

Ambos oferecem alguma forma de reaproveitamento da porção estável do
contexto, com regras próprias sobre tamanho mínimo e duração.

Vale bastante quando o prompt de sistema é grande ou quando você reenvia
os mesmos documentos recuperados em várias chamadas.

Componentes que você monta

Nesta trilha não há plataforma gerenciada, então você escolhe cada peça:

Necessidade Opções
Banco vetorial Extensão vetorial do Postgres, alternativas dedicadas
Busca por palavra-chave Recurso nativo do Postgres ou motor de busca
Orquestração de agente Código próprio ou framework de grafo
Avaliação Bibliotecas integradas a framework de teste
Observabilidade Plataformas de rastreamento de chamadas
Deploy Qualquer lugar

Recomendação para o curso: Postgres com extensão vetorial resolve
armazenamento vetorial e busca textual num só sistema. Menos peças
móveis, menos coisas para depurar enquanto você aprende o resto.

Frameworks de orquestração

Existem frameworks maduros para orquestrar agentes com máquinas de estado.

Use depois de construir na mão. Frameworks escondem o funcionamento —
excelente para produtividade, ruim para aprendizado inicial. Quando você
já sabe o que está sendo abstraído, a abstração vira ganho puro.

Vantagens e limitações

Vantagens: portabilidade entre nuvens, compreensão profunda,
independência de fornecedor de plataforma, começo imediato.

Limitações: você monta e opera mais coisas; governança corporativa
(identidade, auditoria, residência de dados) fica por sua conta.

Documentação

Consulte sempre a documentação oficial de cada provedor. Os pontos que
você vai precisar em cada módulo:

Módulo O que procurar
1 Referência de API, modelos disponíveis, preços
2 Saída estruturada, engenharia de prompt
3 (bibliotecas de avaliação, não do provedor)
4 Tabela de preços, cache de contexto
6 Modelos de embedding
8 Chamada de função e uso de ferramentas
