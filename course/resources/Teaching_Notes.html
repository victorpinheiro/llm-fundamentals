Notas para Quem For Ministrar

Formato sugerido

O material foi desenhado para autoestudo, mas funciona bem em turma com
adaptações mínimas.

Turma semanal (16–20 encontros)

Encontro Formato Duração
Conceito Apresentação + discussão 1h
Projeto Sessão de trabalho com mentoria 2–3h

Cada módulo gera um ou dois encontros. Projetos maiores (P5, P7, P9)
podem ocupar três sessões.

Bootcamp intensivo (5 dias)

Dia Conteúdo
1 Módulos 1–3, projetos P1–P2
2 Módulos 4–5, projetos P3–P4
3 Módulos 6–7, projetos P5–P6
4 Módulos 8–9, projetos P7–P8
5 Módulos 10–11, projeto P9 (início)

Intensivo demais para absorção real — sirva como introdução seguida de
mentoria assíncrona.

Avaliação de alunos

Os projetos já têm critérios objetivos (Definition of Done). Use-os.

O que diferencia um trabalho excelente de um adequado não é complexidade,
é a presença de:

  1. Registro de decisão — por que cada escolha foi feita
  2. Medição honesta — incluindo quando o resultado foi "não compensou"
  3. Limitações reconhecidas — o que faltou e por quê
  4. Clareza de escrita — alguém que não participou entende o trabalho

Erros comuns de quem ministra

  • Demonstrar sempre a solução complexa (agentes) e nunca a simples
  • Não mostrar falhas — sistemas de IA que só funcionam em demonstração
    ensinam a errar com confiança
  • Pular avaliação por falta de tempo — é exatamente o que alunos vão
    fazer em produção se não praticarem
  • Usar apenas exemplos triviais que nunca falham
  • Não reservar tempo para a descoberta do projeto final —
    alunos tendem a pular direto para o código

Sobre manter o material atualizado

Módulos conceituais (01_Modules/) envelhecem lentamente.
Guias de trilha (03_Tracks/) envelhecem rápido.

Se estiver ministrando, revise os guias de trilha no início de cada
ciclo. O Aviso de Volatilidade existe por um motivo.
