P1 — Primeira Integração com Saída Estruturada

Módulo: Módulo 1 — Fundamentos de Modelos de Linguagem · Tempo: 8–12h · Degrau 1

Objetivo

Integrar um modelo com saída estruturada confiável e instrumentar custo
e latência. Comparar pelo menos dois modelos na mesma tarefa.

Cenário

Um sistema de triagem que recebe pedidos de suporte em texto livre e
produz classificação estruturada.

O texto de entrada pode vir malformado — abreviado, sem pontuação, com
erros de digitação, em idioma inesperado. Sistemas reais recebem isso.

Especificação

Input: "sistema fora do ar desde ontem, ninguem consegue acessar, urgente"

Output:
{
  "category": "outage",
  "urgency": 5,
  "responsible_area": "infrastructure",
  "summary": "System unavailable since yesterday, access blocked",
  "requires_escalation": true,
  "_meta": {
    "model": "...",
    "latency_ms": 0,
    "input_tokens": 0,
    "output_tokens": 0,
    "cost_usd": 0.0
  }
}

Requisitos

  • Saída estruturada nativa do provedor — zero expressão regular
  • Validação por modelo de dados no código
  • Temperatura zero
  • Instrumentação de latência, tokens e custo em toda chamada
  • Mesmos 20 casos executados em pelo menos dois modelos
  • Tratamento de entrada malformada

Trilha A: compare dois provedores diferentes.
Trilha B: autenticação por credencial padrão; compare duas camadas
de modelo. Nunca use chave de API.

Passo a passo

Passo 1 — Defina o esquema de saída (schemas.py)

Antes de escrever qualquer prompt, defina exatamente o que você espera receber. O Pydantic serve como contrato entre o modelo e o seu código — se a saída não bater, a validação explode imediatamente em vez de propagar lixo silenciosamente.

# schemas.py
from pydantic import BaseModel, Field
from typing import Literal


class InstrumentationMeta(BaseModel):
    """Instrumentation metadata for each LLM call."""
    model: str
    latency_ms: float = Field(ge=0, description="Call latency in milliseconds")
    input_tokens: int = Field(ge=0)
    output_tokens: int = Field(ge=0)
    cost_usd: float = Field(ge=0, description="Estimated cost in dollars")


class TicketClassification(BaseModel):
    """Result of classifying a support ticket."""
    category: Literal[
        "outage",
        "slowness",
        "functional_error",
        "question",
        "request",
        "security",
    ]
    urgency: int = Field(ge=1, le=5, description="1=low, 5=critical")
    responsible_area: Literal[
        "infrastructure",
        "backend",
        "frontend",
        "data",
        "security",
        "support_l1",
    ]
    summary: str = Field(max_length=200, description="Clean summary of the request")
    requires_escalation: bool

    _meta: InstrumentationMeta | None = None

Passo 2 — Escreva o prompt de classificação

O prompt é o coração do sistema. Ele deve ser preciso, com exemplos, e deixar claro o que fazer com entradas ambíguas.

# prompt.py
SYSTEM_PROMPT = """You are a technical support ticket triage system.

Your task: receive the text of a support ticket and produce a structured classification.

## Rules
1. category: choose from outage, slowness, functional_error, question, request, security.
2. urgency: integer from 1 (low) to 5 (critical).
   - 5 = system down, data leaking, or all users impacted.
   - 4 = critical functionality degraded, workaround is difficult.
   - 3 = problem impacts some users, workaround exists.
   - 2 = inconvenience, does not block work.
   - 1 = question or improvement request.
3. responsible_area: choose from infrastructure, backend, frontend, data, security, support_l1.
4. summary: rewrite the request in at most 200 characters, fixing errors and preserving meaning.
5. requires_escalation: true if urgency >= 4.

## Malformed inputs
- If the text is empty or incomprehensible, classify as category="question", urgency=1, responsible_area="support_l1".
- If the language is not English, still classify based on the content.

Respond ONLY with the structured JSON, no additional text."""

Passo 3 — Implemente a saída estruturada

Cada provedor tem seu próprio mecanismo para garantir que a resposta do modelo siga um schema JSON. Aqui está a implementação completa para cada trilha.

Trilha A — OpenAI (com response_format)

# providers/openai_provider.py
import os
import time
import json
from dotenv import load_dotenv
from openai import OpenAI
from schemas import TicketClassification, InstrumentationMeta
from prompt import SYSTEM_PROMPT

load_dotenv()
client = OpenAI()

# Prices per 1M tokens (check the pricing page for current values)
PRICE_INPUT = 0.15   # gpt-4o-mini input
PRICE_OUTPUT = 0.60  # gpt-4o-mini output
MODEL = "gpt-4o-mini"


def classify(text: str) -> TicketClassification:
    start_time = time.time()

    response = client.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": text},
        ],
        temperature=0,
        response_format={
            "type": "json_schema",
            "json_schema": {
                "name": "TicketClassification",
                "strict": True,
                "schema": TicketClassification.model_json_schema(),
            },
        },
    )

    latency_ms = (time.time() - start_time) * 1000
    data = json.loads(response.choices[0].message.content)
    result = TicketClassification(**data)

    result._meta = InstrumentationMeta(
        model=MODEL,
        latency_ms=round(latency_ms, 1),
        input_tokens=response.usage.prompt_tokens,
        output_tokens=response.usage.completion_tokens,
        cost_usd=round(
            (response.usage.prompt_tokens * PRICE_INPUT
             + response.usage.completion_tokens * PRICE_OUTPUT) / 1_000_000,
            6,
        ),
    )
    return result

Trilha A — Anthropic (com tool use)

A Anthropic não tem um parâmetro response_format nativo como a OpenAI. Em vez disso, use tool use: defina uma "ferramenta" cujo schema é a sua classificação e instrua o modelo a chamá-la. O modelo retorna os argumentos estruturados da ferramenta.

# providers/anthropic_provider.py
import os
import time
from dotenv import load_dotenv
import anthropic
from schemas import TicketClassification, InstrumentationMeta
from prompt import SYSTEM_PROMPT

load_dotenv()
client = anthropic.Anthropic()

PRICE_INPUT = 3.00    # claude-sonnet input per 1M tokens
PRICE_OUTPUT = 15.00  # claude-sonnet output per 1M tokens
MODEL = "claude-sonnet-4-20250514"

TOOL_DEFINITION = {
    "name": "record_classification",
    "description": "Records the structured classification of a support ticket.",
    "input_schema": TicketClassification.model_json_schema(),
}


def classify(text: str) -> TicketClassification:
    start_time = time.time()

    response = client.messages.create(
        model=MODEL,
        max_tokens=512,
        system=SYSTEM_PROMPT + "\n\nUse the record_classification tool to return the result.",
        messages=[{"role": "user", "content": text}],
        tools=[TOOL_DEFINITION],
        tool_choice={"type": "tool", "name": "record_classification"},
        temperature=0,
    )

    latency_ms = (time.time() - start_time) * 1000

    # The result is in the tool_use block
    tool_block = next(b for b in response.content if b.type == "tool_use")
    result = TicketClassification(**tool_block.input)

    result._meta = InstrumentationMeta(
        model=MODEL,
        latency_ms=round(latency_ms, 1),
        input_tokens=response.usage.input_tokens,
        output_tokens=response.usage.output_tokens,
        cost_usd=round(
            (response.usage.input_tokens * PRICE_INPUT
             + response.usage.output_tokens * PRICE_OUTPUT) / 1_000_000,
            6,
        ),
    )
    return result

Trilha B — Vertex AI (com response_schema)

# providers/vertexai_provider.py
import os
import time
from dotenv import load_dotenv
import vertexai
from vertexai.generative_models import GenerativeModel, GenerationConfig
from schemas import TicketClassification, InstrumentationMeta
from prompt import SYSTEM_PROMPT

load_dotenv()
vertexai.init(
    project=os.getenv("GOOGLE_CLOUD_PROJECT"),
    location=os.getenv("GOOGLE_CLOUD_LOCATION", "us-central1"),
)

# Prices per 1M tokens — Gemini 2.0 Flash (check the pricing page)
PRICE_INPUT = 0.10
PRICE_OUTPUT = 0.40
MODEL_NAME = "gemini-2.0-flash"

model = GenerativeModel(
    MODEL_NAME,
    system_instruction=SYSTEM_PROMPT,
)


def classify(text: str) -> TicketClassification:
    start_time = time.time()

    response = model.generate_content(
        text,
        generation_config=GenerationConfig(
            temperature=0,
            response_mime_type="application/json",
            response_schema=TicketClassification.model_json_schema(),
        ),
    )

    latency_ms = (time.time() - start_time) * 1000
    import json
    data = json.loads(response.text)
    result = TicketClassification(**data)

    result._meta = InstrumentationMeta(
        model=MODEL_NAME,
        latency_ms=round(latency_ms, 1),
        input_tokens=response.usage_metadata.prompt_token_count,
        output_tokens=response.usage_metadata.candidates_token_count,
        cost_usd=round(
            (response.usage_metadata.prompt_token_count * PRICE_INPUT
             + response.usage_metadata.candidates_token_count * PRICE_OUTPUT) / 1_000_000,
            6,
        ),
    )
    return result

Track C — Gemini (AI Studio)

# providers/gemini_provider.py
import os
import time
import json
from dotenv import load_dotenv
from google import genai
from google.genai import types
from schemas import TicketClassification, InstrumentationMeta
from prompt import SYSTEM_PROMPT

load_dotenv()
client = genai.Client(api_key=os.getenv("GEMINI_API_KEY"))

MODEL_NAME = "gemini-2.0-flash"


def classify(text: str) -> TicketClassification:
    start_time = time.time()

    response = client.models.generate_content(
        model=MODEL_NAME,
        contents=f"{SYSTEM_PROMPT}\n\nTicket:\n{text}",
        config=types.GenerateContentConfig(
            temperature=0,
            response_mime_type="application/json",
            response_schema=TicketClassification,
        ),
    )

    latency_ms = (time.time() - start_time) * 1000
    data = json.loads(response.text)
    result = TicketClassification(**data)

    result._meta = InstrumentationMeta(
        model=MODEL_NAME,
        latency_ms=round(latency_ms, 1),
        input_tokens=response.usage_metadata.prompt_token_count,
        output_tokens=response.usage_metadata.candidates_token_count,
        cost_usd=0.0,  # free tier
    )
    return result

Passo 4 — Entenda a instrumentação

Toda chamada a LLM em produção precisa registrar três números: latência, tokens e custo. No código acima, isso já está implementado no objeto InstrumentationMeta. A fórmula de custo é simples:

# cost = (input_tokens * price_input + output_tokens * price_output) / 1_000_000
# Prices are per 1 million tokens — always check the official page:
# - OpenAI:    https://openai.com/api/pricing/
# - Anthropic: https://docs.anthropic.com/en/docs/about-claude/models
# - Vertex AI: https://cloud.google.com/vertex-ai/generative-ai/pricing

No P1 você coleta esses números manualmente. A partir do P3, isso vai virar pipeline automatizado.

Passo 5 — Construa o script de comparação (compare.py)

Este script executa os mesmos 20 casos de teste em dois ou mais provedores e gera a tabela comparativa.

# compare.py
import json
import sys
from pathlib import Path

# Import the providers you implemented
# Track A:
from providers.openai_provider import classify as classify_openai
from providers.anthropic_provider import classify as classify_anthropic
# Track B:
# from providers.vertexai_provider import classify as classify_vertexai_flash
# (create a second provider with a different model to compare)
# Track C:
# from providers.gemini_provider import classify as classify_gemini
# from providers.groq_provider import classify as classify_groq
# from providers.ollama_provider import classify as classify_ollama

PROVIDERS = {
    # Track A
    "openai_gpt4o_mini": classify_openai,
    "anthropic_sonnet": classify_anthropic,
    # Track B
    # "vertexai_flash": classify_vertexai_flash,
    # Track C
    # "gemini_flash": classify_gemini,
    # "groq_llama70b": classify_groq,
    # "ollama_llama32": classify_ollama,
}


def load_cases(path: str = "test_cases.json") -> list[dict]:
    with open(path) as f:
        return json.load(f)


def run_comparison():
    cases = load_cases()
    results = {name: [] for name in PROVIDERS}

    for i, case in enumerate(cases, 1):
        text = case["text"]
        print(f"\n--- Case {i}/{len(cases)}: {text[:60]}...")

        for name, fn in PROVIDERS.items():
            try:
                result = fn(text)
                results[name].append({
                    "case": i,
                    "text": text,
                    "classification": result.model_dump(),
                    "meta": result._meta.model_dump() if result._meta else {},
                    "error": None,
                })
                meta = result._meta
                print(f"  {name}: {result.category} (urg={result.urgency}) "
                      f"— {meta.latency_ms:.0f}ms, ${meta.cost_usd:.6f}")
            except Exception as e:
                results[name].append({
                    "case": i,
                    "text": text,
                    "classification": None,
                    "meta": {},
                    "error": str(e),
                })
                print(f"  {name}: ERROR — {e}")

    # Save results
    Path("results").mkdir(exist_ok=True)
    with open("results/comparison.json", "w") as f:
        json.dump(results, f, indent=2, ensure_ascii=False)

    # Print summary
    print("\n\n=== SUMMARY ===")
    for name, entries in results.items():
        successes = [r for r in entries if r["error"] is None]
        errors = len(entries) - len(successes)
        if successes:
            avg_latency = sum(r["meta"]["latency_ms"] for r in successes) / len(successes)
            total_cost = sum(r["meta"]["cost_usd"] for r in successes)
            print(f"\n{name}:")
            print(f"  Successes: {len(successes)}/{len(entries)}")
            print(f"  Avg latency: {avg_latency:.0f}ms")
            print(f"  Total cost (20 cases): ${total_cost:.6f}")
            print(f"  Projected cost (1000/day): ${total_cost / len(successes) * 1000:.4f}/day")
            if errors:
                print(f"  Errors: {errors}")


if __name__ == "__main__":
    run_comparison()

Passo 6 — Trate entradas malformadas

Sistemas reais recebem lixo. Envolva cada chamada em tratamento de erro robusto:

# In your main classifier.py, wrap the call:
from pydantic import ValidationError

def classify_safe(text: str, classify_fn) -> TicketClassification | dict:
    """Attempts to classify; raises on failure."""
    if not text or not text.strip():
        return TicketClassification(
            category="question",
            urgency=1,
            responsible_area="support_l1",
            summary="Empty input received",
            requires_escalation=False,
        )
    try:
        return classify_fn(text)
    except ValidationError as e:
        print(f"[ERROR] Model output failed validation: {e}")
        raise
    except Exception as e:
        print(f"[ERROR] Model call failed: {e}")
        raise

Teste com entradas intencionalmente ruins: string vazia, caracteres aleatórios, texto em outro idioma, e textos com mais de 1000 palavras.

Como criar bons casos de teste

Você precisa de 20 casos em test_cases.json. Não invente 20 variações do mesmo tema — distribua intencionalmente:

Distribuição recomendada

  • 5 casos claros (happy path): tickets bem escritos, sem ambiguidade. Servem de baseline.
  • 5 casos ambíguos: textos que poderiam ser classificados em mais de uma categoria. O modelo vai errar alguns — e tudo bem, você quer saber como ele erra.
  • 5 casos com ruído: abreviações, erros de digitação, gírias, texto em inglês ou misturado.
  • 5 casos de borda: texto vazio, um único emoji, texto muito longo, pedido que não é suporte.
