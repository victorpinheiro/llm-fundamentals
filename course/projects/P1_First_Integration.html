P1 — Primeira Integração com Saída Estruturada

Módulo: Módulo 1 — Fundamentos de Modelos de Linguagem · Tempo: 8–12h · Degrau 1

Objetivo

Integrar um modelo com saída estruturada confiável e instrumentar custo
e latência. Comparar pelo menos dois modelos na mesma tarefa.

Cenário

Um sistema de triagem que recebe pedidos de suporte em texto livre e
produz classificação estruturada.

O texto de entrada pode vir malformado — abreviado, sem pontuação, com
erros de digitação, em idioma inesperado. Sistemas reais recebem isso.

Especificação

Entrada: "sistema fora do ar desde ontem, ninguem consegue acessar, urgente"

Saída:
{
  "categoria": "indisponibilidade",
  "urgencia": 5,
  "area_responsavel": "infraestrutura",
  "resumo": "Sistema indisponível desde ontem, acesso bloqueado",
  "requer_escalonamento": true,
  "_meta": {
    "modelo": "...",
    "latencia_ms": 0,
    "tokens_entrada": 0,
    "tokens_saida": 0,
    "custo_usd": 0.0
  }
}

Requisitos

  • Saída estruturada nativa do provedor — zero expressão regular
  • Validação por modelo de dados no código
  • Temperatura zero
  • Instrumentação de latência, tokens e custo em toda chamada
  • Mesmos 20 casos executados em pelo menos dois modelos
  • Tratamento de entrada malformada

Trilha A: compare dois provedores diferentes.
Trilha B: autenticação por credencial padrão; compare duas camadas
de modelo. Nunca use chave de API.

Passo a passo

Passo 1 — Defina o esquema de saída (esquemas.py)

Antes de escrever qualquer prompt, defina exatamente o que você espera receber. O Pydantic serve como contrato entre o modelo e o seu código — se a saída não bater, a validação explode imediatamente em vez de propagar lixo silenciosamente.

# esquemas.py
from pydantic import BaseModel, Field
from typing import Literal


class MetaInstrumentacao(BaseModel):
    """Metadados de instrumentação de cada chamada."""
    modelo: str
    latencia_ms: float = Field(ge=0, description="Latência da chamada em milissegundos")
    tokens_entrada: int = Field(ge=0)
    tokens_saida: int = Field(ge=0)
    custo_usd: float = Field(ge=0, description="Custo estimado em dólares")


class ClassificacaoTicket(BaseModel):
    """Resultado da classificação de um ticket de suporte."""
    categoria: Literal[
        "indisponibilidade",
        "lentidao",
        "erro_funcional",
        "duvida",
        "solicitacao",
        "seguranca",
    ]
    urgencia: int = Field(ge=1, le=5, description="1=baixa, 5=crítica")
    area_responsavel: Literal[
        "infraestrutura",
        "backend",
        "frontend",
        "dados",
        "seguranca",
        "suporte_n1",
    ]
    resumo: str = Field(max_length=200, description="Resumo limpo do pedido")
    requer_escalonamento: bool

    _meta: MetaInstrumentacao | None = None

Passo 2 — Escreva o prompt de classificação

O prompt é o coração do sistema. Ele deve ser preciso, com exemplos, e deixar claro o que fazer com entradas ambíguas.

# prompt.py
SYSTEM_PROMPT = """Você é um sistema de triagem de tickets de suporte técnico.

Sua tarefa: receber o texto de um ticket e produzir uma classificação estruturada.

## Regras
1. categoria: escolha entre indisponibilidade, lentidao, erro_funcional, duvida, solicitacao, seguranca.
2. urgencia: inteiro de 1 (baixa) a 5 (crítica).
   - 5 = sistema fora do ar, dados vazando, ou impacto em todos os usuários.
   - 4 = funcionalidade crítica degradada, workaround difícil.
   - 3 = problema impacta parte dos usuários, existe workaround.
   - 2 = inconveniente, não bloqueia trabalho.
   - 1 = dúvida ou melhoria.
3. area_responsavel: escolha entre infraestrutura, backend, frontend, dados, seguranca, suporte_n1.
4. resumo: reescreva o pedido em no máximo 200 caracteres, corrigindo erros e mantendo o sentido.
5. requer_escalonamento: true se urgencia >= 4.

## Entradas malformadas
- Se o texto estiver vazio ou for incompreensível, classifique como categoria="duvida", urgencia=1, area_responsavel="suporte_n1".
- Se o idioma não for português, ainda assim classifique pelo conteúdo.

Responda APENAS com o JSON estruturado, sem texto adicional."""

Passo 3 — Implemente a saída estruturada

Cada provedor tem seu próprio mecanismo para garantir que a resposta do modelo siga um schema JSON. Aqui está a implementação completa para cada trilha.

Trilha A — OpenAI (com response_format)

# provedores/openai_provider.py
import os
import time
import json
from dotenv import load_dotenv
from openai import OpenAI
from esquemas import ClassificacaoTicket, MetaInstrumentacao
from prompt import SYSTEM_PROMPT

load_dotenv()
client = OpenAI()

# Preços por 1M tokens (consulte a página de pricing para valores atuais)
PRECO_INPUT = 0.15   # gpt-4o-mini input
PRECO_OUTPUT = 0.60  # gpt-4o-mini output
MODELO = "gpt-4o-mini"


def classificar(texto: str) -> ClassificacaoTicket:
    inicio = time.time()

    resposta = client.chat.completions.create(
        model=MODELO,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": texto},
        ],
        temperature=0,
        response_format={
            "type": "json_schema",
            "json_schema": {
                "name": "ClassificacaoTicket",
                "strict": True,
                "schema": ClassificacaoTicket.model_json_schema(),
            },
        },
    )

    latencia_ms = (time.time() - inicio) * 1000
    dados = json.loads(resposta.choices[0].message.content)
    resultado = ClassificacaoTicket(**dados)

    resultado._meta = MetaInstrumentacao(
        modelo=MODELO,
        latencia_ms=round(latencia_ms, 1),
        tokens_entrada=resposta.usage.prompt_tokens,
        tokens_saida=resposta.usage.completion_tokens,
        custo_usd=round(
            (resposta.usage.prompt_tokens * PRECO_INPUT
             + resposta.usage.completion_tokens * PRECO_OUTPUT) / 1_000_000,
            6,
        ),
    )
    return resultado

Trilha A — Anthropic (com tool use)

A Anthropic não tem um parâmetro response_format nativo como a OpenAI. Em vez disso, use tool use: defina uma "ferramenta" cujo schema é a sua classificação e instrua o modelo a chamá-la. O modelo retorna os argumentos estruturados da ferramenta.

# provedores/anthropic_provider.py
import os
import time
from dotenv import load_dotenv
import anthropic
from esquemas import ClassificacaoTicket, MetaInstrumentacao
from prompt import SYSTEM_PROMPT

load_dotenv()
client = anthropic.Anthropic()

PRECO_INPUT = 3.00    # claude-sonnet input por 1M tokens
PRECO_OUTPUT = 15.00  # claude-sonnet output por 1M tokens
MODELO = "claude-sonnet-4-20250514"

TOOL_DEFINITION = {
    "name": "registrar_classificacao",
    "description": "Registra a classificação estruturada do ticket de suporte.",
    "input_schema": ClassificacaoTicket.model_json_schema(),
}


def classificar(texto: str) -> ClassificacaoTicket:
    inicio = time.time()

    resposta = client.messages.create(
        model=MODELO,
        max_tokens=512,
        system=SYSTEM_PROMPT + "\n\nUse a ferramenta registrar_classificacao para retornar o resultado.",
        messages=[{"role": "user", "content": texto}],
        tools=[TOOL_DEFINITION],
        tool_choice={"type": "tool", "name": "registrar_classificacao"},
        temperature=0,
    )

    latencia_ms = (time.time() - inicio) * 1000

    # O resultado está no bloco tool_use
    tool_block = next(b for b in resposta.content if b.type == "tool_use")
    resultado = ClassificacaoTicket(**tool_block.input)

    resultado._meta = MetaInstrumentacao(
        modelo=MODELO,
        latencia_ms=round(latencia_ms, 1),
        tokens_entrada=resposta.usage.input_tokens,
        tokens_saida=resposta.usage.output_tokens,
        custo_usd=round(
            (resposta.usage.input_tokens * PRECO_INPUT
             + resposta.usage.output_tokens * PRECO_OUTPUT) / 1_000_000,
            6,
        ),
    )
    return resultado

Trilha B — Vertex AI (com response_schema)

# provedores/vertexai_provider.py
import os
import time
from dotenv import load_dotenv
import vertexai
from vertexai.generative_models import GenerativeModel, GenerationConfig
from esquemas import ClassificacaoTicket, MetaInstrumentacao
from prompt import SYSTEM_PROMPT

load_dotenv()
vertexai.init(
    project=os.getenv("GOOGLE_CLOUD_PROJECT"),
    location=os.getenv("GOOGLE_CLOUD_LOCATION", "us-central1"),
)

# Preços por 1M tokens — Gemini 2.0 Flash (consulte a página de pricing)
PRECO_INPUT = 0.10
PRECO_OUTPUT = 0.40
MODELO_NOME = "gemini-2.0-flash"

modelo = GenerativeModel(
    MODELO_NOME,
    system_instruction=SYSTEM_PROMPT,
)


def classificar(texto: str) -> ClassificacaoTicket:
    inicio = time.time()

    resposta = modelo.generate_content(
        texto,
        generation_config=GenerationConfig(
            temperature=0,
            response_mime_type="application/json",
            response_schema=ClassificacaoTicket.model_json_schema(),
        ),
    )

    latencia_ms = (time.time() - inicio) * 1000
    import json
    dados = json.loads(resposta.text)
    resultado = ClassificacaoTicket(**dados)

    resultado._meta = MetaInstrumentacao(
        modelo=MODELO_NOME,
        latencia_ms=round(latencia_ms, 1),
        tokens_entrada=resposta.usage_metadata.prompt_token_count,
        tokens_saida=resposta.usage_metadata.candidates_token_count,
        custo_usd=round(
            (resposta.usage_metadata.prompt_token_count * PRECO_INPUT
             + resposta.usage_metadata.candidates_token_count * PRECO_OUTPUT) / 1_000_000,
            6,
        ),
    )
    return resultado

Passo 4 — Entenda a instrumentação

Toda chamada a LLM em produção precisa registrar três números: latência, tokens e custo. No código acima, isso já está implementado no objeto MetaInstrumentacao. A fórmula de custo é simples:

# Custo = (tokens_entrada * preço_input + tokens_saida * preço_output) / 1_000_000
# Os preços são por 1 milhão de tokens — consulte sempre a página oficial:
# - OpenAI:    https://openai.com/api/pricing/
# - Anthropic: https://docs.anthropic.com/en/docs/about-claude/models
# - Vertex AI: https://cloud.google.com/vertex-ai/generative-ai/pricing

No P1 você coleta esses números manualmente. A partir do P3, isso vai virar pipeline automatizado.

Passo 5 — Construa o script de comparação (comparar.py)

Este script executa os mesmos 20 casos de teste em dois ou mais provedores e gera a tabela comparativa.

# comparar.py
import json
import sys
from pathlib import Path

# Importe os provedores que você implementou
# Trilha A:
from provedores.openai_provider import classificar as classificar_openai
from provedores.anthropic_provider import classificar as classificar_anthropic
# Trilha B:
# from provedores.vertexai_provider import classificar as classificar_vertexai_flash
# (crie um segundo provider com modelo diferente para comparar)

PROVEDORES = {
    "openai_gpt4o_mini": classificar_openai,
    "anthropic_sonnet": classificar_anthropic,
    # "vertexai_flash": classificar_vertexai_flash,
}


def carregar_casos(caminho: str = "casos_teste.json") -> list[dict]:
    with open(caminho) as f:
        return json.load(f)


def executar_comparacao():
    casos = carregar_casos()
    resultados = {nome: [] for nome in PROVEDORES}

    for i, caso in enumerate(casos, 1):
        texto = caso["texto"]
        print(f"\n--- Caso {i}/{len(casos)}: {texto[:60]}...")

        for nome, fn in PROVEDORES.items():
            try:
                resultado = fn(texto)
                resultados[nome].append({
                    "caso": i,
                    "texto": texto,
                    "classificacao": resultado.model_dump(),
                    "meta": resultado._meta.model_dump() if resultado._meta else {},
                    "erro": None,
                })
                meta = resultado._meta
                print(f"  {nome}: {resultado.categoria} (urg={resultado.urgencia}) "
                      f"— {meta.latencia_ms:.0f}ms, ${meta.custo_usd:.6f}")
            except Exception as e:
                resultados[nome].append({
                    "caso": i,
                    "texto": texto,
                    "classificacao": None,
                    "meta": {},
                    "erro": str(e),
                })
                print(f"  {nome}: ERRO — {e}")

    # Salva resultados
    Path("resultados").mkdir(exist_ok=True)
    with open("resultados/comparacao.json", "w") as f:
        json.dump(resultados, f, indent=2, ensure_ascii=False)

    # Imprime resumo
    print("\n\n=== RESUMO ===")
    for nome, lista in resultados.items():
        sucessos = [r for r in lista if r["erro"] is None]
        erros = len(lista) - len(sucessos)
        if sucessos:
            lat_media = sum(r["meta"]["latencia_ms"] for r in sucessos) / len(sucessos)
            custo_total = sum(r["meta"]["custo_usd"] for r in sucessos)
            print(f"\n{nome}:")
            print(f"  Sucessos: {len(sucessos)}/{len(lista)}")
            print(f"  Latência média: {lat_media:.0f}ms")
            print(f"  Custo total (20 casos): ${custo_total:.6f}")
            print(f"  Custo projetado (1000/dia): ${custo_total / len(sucessos) * 1000:.4f}/dia")
            if erros:
                print(f"  Erros: {erros}")


if __name__ == "__main__":
    executar_comparacao()

Passo 6 — Trate entradas malformadas

Sistemas reais recebem lixo. Envolva cada chamada em tratamento de erro robusto:

# No seu classificador.py principal, encapsule a chamada:
from pydantic import ValidationError

def classificar_seguro(texto: str, fn_classificar) -> ClassificacaoTicket | dict:
    """Tenta classificar; retorna erro estruturado em caso de falha."""
    if not texto or not texto.strip():
        return ClassificacaoTicket(
            categoria="duvida",
            urgencia=1,
            area_responsavel="suporte_n1",
            resumo="Entrada vazia recebida",
            requer_escalonamento=False,
        )
    try:
        return fn_classificar(texto)
    except ValidationError as e:
        print(f"[ERRO] Saída do modelo não passou na validação: {e}")
        raise
    except Exception as e:
        print(f"[ERRO] Falha na chamada ao modelo: {e}")
        raise

Teste com entradas intencionalmente ruins: string vazia, caracteres aleatórios, texto em outro idioma, e textos com mais de 1000 palavras.

Como criar bons casos de teste

Você precisa de 20 casos em casos_teste.json. Não invente 20 variações do mesmo tema — distribua intencionalmente:

Distribuição recomendada

  • 5 casos claros (happy path): tickets bem escritos, sem ambiguidade. Servem de baseline.
  • 5 casos ambíguos: textos que poderiam ser classificados em mais de uma categoria. O modelo vai errar alguns — e tudo bem, você quer saber como ele erra.
  • 5 casos com ruído: abreviações, erros de digitação, gírias, texto em inglês ou misturado.
  • 5 casos de borda: texto vazio, um único emoji, texto muito longo, pedido que não é suporte.
