P5 — Sistema de Recuperação

Módulo: Módulo 6 — Geração Aumentada por Recuperação · Tempo: 20–26h · Degrau 2

Pré-condição

Documente por escrito antes de codificar:

  1. Precisa de conhecimento externo ao modelo? Por quê?
  2. O acervo cabe na janela de contexto? Calcule.
  3. Citação de fonte é obrigatória?
  4. A plataforma já oferece recuperação gerenciada? Se sim, por que
    construir do zero?

Sem esse documento, o projeto está incompleto.

Cenário

Base de documentação de processos e políticas.
Perguntas do tipo: "qual o procedimento para X?"

Use documentos públicos ou sintéticos. Não use material interno
confidencial de nenhuma organização num projeto de aprendizado.

Pipeline

Documents
  → chunking decision (justified)
  → embeddings
  → index with metadata

Question
  → vector search + keyword search
  → reciprocal rank fusion
  → permission filter
  → grounded prompt
  → response with citation

Passo a passo

Passo 2 — Implemente a fragmentação (chunking)

Fragmentação é cortar documentos em pedaços menores para indexação. O tamanho do chunk afeta diretamente a qualidade:

  • 500 chars — alta precisão, mas pode cortar no meio de uma ideia
  • 1000 chars — bom equilíbrio para a maioria dos casos
  • 2000 chars — preserva mais contexto, mas reduz precisão de busca

Crie ingestion.py:

"""ingestion.py — loads documents, chunks and indexes them."""
import os, hashlib
from pathlib import Path

# Option 1: LangChain text splitters (pip install langchain-text-splitters)
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,        # overlap to avoid cutting ideas
    separators=["\n## ", "\n### ", "\n\n", "\n", ". ", " "],
)

def load_documents(directory: str) -> list[dict]:
    """Load all .md files from a directory and chunk them."""
    chunks = []
    for file in sorted(Path(directory).glob("*.md")):
        text = file.read_text(encoding="utf-8")
        pieces = splitter.split_text(text)
        for i, piece in enumerate(pieces):
            chunks.append({
                "id": hashlib.md5(f"{file.name}:{i}".encode()).hexdigest(),
                "text": piece,
                "metadata": {
                    "source": file.name,
                    "chunk_index": i,
                    "total_chunks": len(pieces),
                },
            })
    print(f"Loaded {len(chunks)} chunks from {directory}")
    return chunks

Passo 3 — Gere embeddings

Embeddings convertem texto em vetores numéricos para busca por similaridade.

Trilha A — OpenAI:

from openai import OpenAI

client = OpenAI()

def generate_embeddings(texts: list[str]) -> list[list[float]]:
    """Generate embeddings for a list of texts."""
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=texts,
    )
    return [item.embedding for item in response.data]

Trilha B — Vertex AI:

from google import genai

Track C — Groq

Groq does not offer an embeddings API. For embeddings, pair Groq (used for generation) with a free embedding source such as Gemini text-embedding-004 above, or Ollama nomic-embed-text below. Use Groq only for the generation step in the RAG pipeline.

Track C — Ollama

Ollama runs locally and offers embeddings via the nomic-embed-text model. Pull the model first: ollama pull nomic-embed-text

import ollama

def generate_embeddings(texts: list[str]) -> list[list[float]]:
    """Generate embeddings with Ollama nomic-embed-text (local, free)."""
    embeddings = []
    for text in texts:
        response = ollama.embeddings(model="nomic-embed-text", prompt=text)
        embeddings.append(response["embedding"])
    return embeddings

Note: Ollama processes one text at a time. For large corpora, this is slower than batched APIs but has zero cost and no rate limits.

Passo 4 — Configure o vector store com ChromaDB

ChromaDB é a opção mais simples para aprendizado: instale com pip install chromadb, sem servidor, sem configuração. Os dados ficam num diretório local.

"""Continuation of ingestion.py — indexing in ChromaDB."""
import chromadb

# Create (or open) the local collection
chroma_client = chromadb.PersistentClient(path="./chroma_db")
collection = chroma_client.get_or_create_collection(
    name="documents",
    metadata={"hnsw:space": "cosine"},   # cosine distance
)

def index_chunks(chunks: list[dict]):
    """Generate embeddings and add to ChromaDB."""
    texts = [c["text"] for c in chunks]
    ids = [c["id"] for c in chunks]
    metadatas = [c["metadata"] for c in chunks]

    # Generate embeddings in batches of 100
    embeddings = []
    for i in range(0, len(texts), 100):
        batch = texts[i:i+100]
        embeddings.extend(generate_embeddings(batch))

    collection.add(
        ids=ids,
        embeddings=embeddings,
        documents=texts,
        metadatas=metadatas,
    )
    print(f"Indexed {len(chunks)} chunks in ChromaDB")

if __name__ == "__main__":
    chunks = load_documents("corpus")
    index_chunks(chunks)

Passo 5 — Implemente busca híbrida

Busca vetorial é boa para similaridade semântica, mas perde termos exatos (siglas, códigos, nomes). BM25 complementa com busca por palavras-chave. A fusão de postos recíprocos (Reciprocal Rank Fusion — RRF) combina os dois rankings.

Algoritmo RRF: para cada documento que aparece em qualquer ranking, some 1 / (k + posição) de cada ranking onde ele aparece. O k é uma constante (tipicamente 60) que controla o peso de posições altas. Ordene pelo score combinado.

"""retriever.py — hybrid search: vector + BM25 with RRF."""
import chromadb
from rank_bm25 import BM25Okapi    # pip install rank_bm25

chroma_client = chromadb.PersistentClient(path="./chroma_db")
collection = chroma_client.get_collection("documents")

# Load all documents for BM25
all_docs = collection.get(include=["documents", "metadatas"])
corpus_text = all_docs["documents"]
corpus_ids = all_docs["ids"]
corpus_meta = all_docs["metadatas"]

# Simple tokenization for BM25
tokenized_corpus = [doc.lower().split() for doc in corpus_text]
bm25 = BM25Okapi(tokenized_corpus)

def vector_search(question: str, top_k: int = 10) -> list[dict]:
    """Search by semantic similarity in ChromaDB."""
    from ingestion import generate_embeddings
    emb = generate_embeddings([question])[0]
    results = collection.query(query_embeddings=[emb], n_results=top_k,
                               include=["documents", "metadatas", "distances"])
    return [
        {"id": results["ids"][0][i], "text": results["documents"][0][i],
         "metadata": results["metadatas"][0][i], "score": 1 - results["distances"][0][i]}
        for i in range(len(results["ids"][0]))
    ]

def bm25_search(question: str, top_k: int = 10) -> list[dict]:
    """Keyword search with BM25."""
    tokens = question.lower().split()
    scores = bm25.get_scores(tokens)
    indices = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)[:top_k]
    return [
        {"id": corpus_ids[i], "text": corpus_text[i],
         "metadata": corpus_meta[i], "score": float(scores[i])}
        for i in indices if scores[i] > 0
    ]

def rrf_fusion(vector_results: list, bm25_results: list, k: int = 60) -> list[dict]:
    """Reciprocal Rank Fusion — combines two rankings."""
    scores = {}
    docs = {}
    for ranking in [vector_results, bm25_results]:
        for position, doc in enumerate(ranking):
            doc_id = doc["id"]
            scores[doc_id] = scores.get(doc_id, 0) + 1.0 / (k + position + 1)
            docs[doc_id] = doc
    sorted_results = sorted(scores.items(), key=lambda x: x[1], reverse=True)
    return [docs[doc_id] for doc_id, _ in sorted_results]

def retrieve(question: str, top_k: int = 5) -> list[dict]:
    """Complete hybrid search: vector + BM25 + RRF."""
    vector = vector_search(question, top_k=10)
    keyword = bm25_search(question, top_k=10)
    combined = rrf_fusion(vector, keyword)
    return combined[:top_k]

Passo 6 — Construa o pipeline RAG

Crie rag.py que conecta recuperação à geração com ancoragem e citação:

"""rag.py — complete RAG pipeline with source citation."""
from retriever import retrieve

# === Track A ===
from openai import OpenAI
client = OpenAI()
MODEL = "gpt-4o-mini"

# === Track B (uncomment) ===
# from google import genai
# client = genai.Client(vertexai=True, project="YOUR_PROJECT", location="us-central1")
# MODEL = "gemini-2.0-flash"

SYSTEM_PROMPT = """\
You are an assistant that answers questions based EXCLUSIVELY on the excerpts
provided below. Rules:

1. Use ONLY information present in the excerpts. Do not make things up.
2. Cite the source in brackets: [filename.md]
3. If no excerpt contains the answer, say: "I could not find this information
   in the available documents."
4. If the answer is only partially in the excerpts, answer what you can and
   indicate what you did not find.
"""

def build_context(chunks: list[dict]) -> str:
    """Format retrieved chunks as context for the prompt."""
    blocks = []
    for i, chunk in enumerate(chunks, 1):
        source = chunk["metadata"]["source"]
        blocks.append(f"[Excerpt {i} — {source}]\n{chunk['text']}")
    return "\n\n---\n\n".join(blocks)

def ask(question: str, top_k: int = 5) -> dict:
    """Complete pipeline: retrieve, build prompt, generate response."""
    # 1. Retrieve relevant chunks
    chunks = retrieve(question, top_k=top_k)

    if not chunks:
        return {
            "answer": "I could not find this information in the available documents.",
            "sources": [],
            "chunks_used": 0,
        }

    # 2. Build prompt with context
    context = build_context(chunks)
    user_prompt = f"Context:\n{context}\n\n---\nQuestion: {question}"

    # 3. Generate response (Track A)
    resp = client.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_prompt},
        ],
        temperature=0,
    )
    answer = resp.choices[0].message.content

Passo 7 — Teste os modos de falha

Cada modo de falha deve virar um teste automatizado. Crie testes/test_modos_falha.py:

"""test_modos_falha.py — testa os 6 modos de falha do RAG."""
from rag import perguntar
from retriever import retrieve

# 1. Semantic mismatch — does a synonym find the document?
def test_semantic_mismatch():
    """Document says 'install', query uses 'configure the setup'."""
    result = retrieve("how to configure the initial setup")
    sources = [c["metadata"]["source"] for c in result]
    assert any("instal" in s.lower() for s in sources), \
        f"Synonym search failed. Sources found: {sources}"

# 2. Chunking — answer that spans two chunks
def test_answer_crosses_chunks():
    """Question whose answer is split across two consecutive chunks."""
    result = ask("Explain the full installation and configuration process")
    assert result["chunks_used"] >= 2, \
        "Expected at least 2 chunks for a complete answer"

# 3. Short cutoff (insufficient top-k)
def test_short_cutoff():
    """Does increasing top_k improve the answer?"""
    r_short = ask("Describe all configuration options", top_k=2)
    r_long = ask("Describe all configuration options", top_k=8)
    assert len(r_long["answer"]) >= len(r_short["answer"]) * 0.8, \
        "Higher top_k did not improve the answer — investigate retrieval"

Requisitos

  • Decisão de fragmentação documentada
  • Busca híbrida com fusão de resultados
  • Metadados preservados (documento, seção, data)
  • Ancoragem: responde "não encontrei" quando não sabe

Modos de falha a testar

Cada um vira um teste automatizado:

  • Descasamento semântico — pergunta com sinônimo encontra o documento?
  • Fragmentação — resposta que atravessa dois trechos
  • Corte curto — aumentar a quantidade recuperada melhora?
  • Índice desatualizado — documento alterado se reflete na busca?
  • Contaminação — trecho irrelevante degrada a resposta?
  • Alucinação apesar do contexto — inventa quando não sabe?
